## Deviations from the plan

- **Browser tool.** The OMP `eval`/`browser` global is not available to this agent, so `browser.open` could not be called; FE-01 – FE-06 were run in Chromium 157.0.8103.79 through a throwaway CDP driver instead (method and mapping in `fe-stack.md`). The verdicts are therefore not `Need info`: the scenarios ran in a real browser with real input events. The FE-05 `eval` step needed the timer-callback variant described there (mechanism checked in review round 1 with `allowUnsafeEvalBlockedByCSP`). FE-06 was run a second time in review round 1 with a second throwaway driver on a fresh stack (`$SFX` `eb8ddf`, owner registered in the same session) because the first record was incomplete; that record replaces the first one in `fe-stack.md`.
- **Session cookie in curl.** The cookie is `Secure`; curl 8.23.0 is inferred not to keep it from `http://patchpoint.localhost:28080` [INFERENCE: the empty jar is deduced from the 401s of steps 8 and 9 and from the `Secure` attribute; the jar itself was not listed]. For OPS-04 the session cookie was taken from the `Set-Cookie` header into a header file under `$RUN` (passed as `-H @file`, never in argv) instead of a cookie jar (explained in `ops-stack.txt` before step 10a). Steps 8 and 9 were run twice: the first attempt used the jar and got 401 each, the repeat sent the header file and got 404 and 403; both are in the evidence. One extra diagnostic login of `.log2` was made outside the numbered steps, so the API log has 4 `login_succeeded` events in the OPS-04 window (`.log2` three times: step 6b, its repeat and the diagnostic; `helpdesk` once) where the plan's steps produce 2.
