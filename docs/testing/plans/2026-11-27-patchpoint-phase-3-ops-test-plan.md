## Changes Summary

Phase 3 puts the Phase 2 API behind a production-like edge. Scope of this plan is what a client sees through the proxy and what the container layout guarantees; the Ansible playbook as a whole (VPS hardening, Let's Encrypt, GHCR deploy) needs a server and is out of scope, except the one bootstrap-certificate command that was changed (BE-16).

Intended contract (compose.yaml, deploy/proxy/templates/, scripts/dev_cert.sh, scripts/stack_smoke.sh):
- One origin: the static UI (`/`) and the API (`/api/`) are served by the proxy (deploy/proxy/templates/includes/patchpoint-app.conf). UI responses carry CSP (`default-src 'none'; … connect-src 'self'; … frame-ancestors 'none'`), `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`, `Cache-Control: no-cache`; there is no `Server` header (`server_tokens off`, `more_clear_headers Server`). `frontend/app.js` is built with `API_BASE_URL = ""`.
- TLS on 8443 (`stack_tls`) with the certificate of `make dev-cert` (SAN `patchpoint.localhost`, `CA:FALSE`, `serverAuth`; scripts/dev_cert.sh:16-24); HSTS is `max-age=${PATCHPOINT_HSTS_MAX_AGE}`, `0` locally. HTTP on 8080 (`stack`) serves the application without redirect locally (`PATCHPOINT_TLS_REDIRECT=off`); ACME challenge paths are never redirected.
- API documentation is off (Phase 2), so `/docs`, `/redoc`, `/openapi.json` end as `404` at the proxy's static location.
- Session cookie of the local stack: name `session` (`PATCHPOINT_COOKIE_NAME` default), `HttpOnly; Secure; SameSite=Strict; Path=/`, no `Domain`. The `__Host-` name is a production setting (env.j2) and is covered by `make stack-smoke`, not here.
- Origin check (middleware): a foreign `Origin` on a state-changing request → `403` `{"detail":"Origin not allowed"}` without ending the session.
- WAF (ModSecurity + OWASP CRS): SQL injection and XSS payloads → `403` `{"detail":"Request blocked by the proxy"}`; the same neutral body for any nginx 403 such as `/metrics/nginx`; the audit log holds 942xxx and 941xxx rule ids and no passwords or tokens. A strong password with quotes and HTML must not be blocked.
- `X-Forwarded-For` is overwritten by the proxy (`proxy_set_header X-Forwarded-For $remote_addr`), so a client-supplied value never becomes `client_ip` in the API log.
- Isolation (compose.yaml): API as UID 10001 and proxy as 101, API `read_only`, `cap_drop: ALL`, `no-new-privileges`, no published port, network `backend` is `internal` (no Internet from the API).
- Rate limit: `POST /api/auth/login` and `/api/auth/register` per client IP, 10 per minute, burst 5 → `429` `{"detail":"Too many requests, try again later"}`.

## BE Test Scenarios

### BE-01: UI over HTTPS carries the security headers and no Server header
- **Area:** static UI location of the proxy
- **Target:** stack_tls
- **Writes:** no
- **Method:** GET /
- **Expected:** `200`; headers `Content-Security-Policy` (with `frame-ancestors 'none'` and `connect-src 'self'`), `Strict-Transport-Security: max-age=0` (local value), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`; no `Server` header (deploy/proxy/templates/includes/patchpoint-app.conf:19-26, deploy/proxy/templates/conf.d/default.conf.template:5-6)

### BE-02: The UI calls the API with relative paths on one origin
- **Target:** stack_tls
- **Method:** GET /app.js, compared with the `index.html` of BE-01
- **Expected:** `200`; `app.js` contains the line `const API_BASE_URL = "";`; neither file mentions `patchpoint.localhost:8000`

### BE-03: The development certificate is a server certificate only and is verified through the trust file
- **Target:** stack_tls
- **Method:** `openssl x509 -ext subjectAltName,basicConstraints,extendedKeyUsage` on `deploy/proxy/dev-tls/fullchain.pem`; `openssl s_client` and `curl` against :8443 with and without `--cacert`
- **Expected:** `DNS:patchpoint.localhost`, `CA:FALSE`, `TLS Web Server Authentication`; handshake TLS 1.3, verify code 0 with the file; `curl` without it fails with exit 60

### BE-04: Local HTTP serves the application; ACME paths are not redirected
- **Target:** stack
- **Method:** GET /api/health; GET /.well-known/acme-challenge/qa-missing
- **Expected:** `200` `{"status":"ok"}` with `Cache-Control: no-store` and no redirect (`PATCHPOINT_TLS_REDIRECT` defaults to `off`, compose.yaml); the ACME path: `404` (default.conf.template:19-23)

### BE-05: API documentation is not reachable through the proxy
- **Target:** stack_tls
- **Method:** GET /docs, /redoc, /openapi.json
- **Expected:** `404` each

### BE-06: A strong password with quotes and HTML passes the WAF
- **Target:** stack_tls
- **Writes:** yes (one account)
- **Method:** POST /api/auth/register `{"username":"qa3.$SFX","password":"Qa'OR'1'='1'--<b>$SFX</b>-xxxx","full_name":"QA Three"}`
- **Expected:** `201` (the CRS exclusions in deploy/proxy/modsecurity/REQUEST-900-EXCLUSION-RULES-BEFORE-CRS.conf leave the password field out of inspection)

### BE-07: Login sets the session cookie with the required attributes
- **Target:** stack_tls
- **Preconditions:** BE-06
- **Method:** POST /api/auth/login with the BE-06 credentials, then GET /api/auth/me with the cookie
- **Expected:** `200`; `Set-Cookie: session=…` with `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/` and no `Domain`; `/api/auth/me` → `200`

### BE-08: A foreign Origin is refused and does not end the session
- **Target:** stack_tls
- **Preconditions:** BE-07
- **Method:** POST /api/auth/logout with `Origin: https://evil.example` and the session cookie; then GET /api/auth/me
- **Expected:** `403` `{"detail":"Origin not allowed"}`; `/api/auth/me` → `200`

### BE-09: The WAF blocks SQL injection in a query parameter
- **Target:** stack_tls
- **Method:** GET /api/tickets?search=1' OR '1'='1 with the session cookie
- **Expected:** `403` `{"detail":"Request blocked by the proxy"}`

### BE-10: The WAF blocks script injection in a body field
- **Target:** stack_tls
- **Method:** POST /api/auth/register with `full_name` `<script>alert(1)</script>`
- **Expected:** `403` `{"detail":"Request blocked by the proxy"}`; no account created

### BE-11: nginx's own 403 uses the same neutral message
- **Target:** stack_tls
- **Method:** GET /metrics/nginx
- **Expected:** `403` `{"detail":"Request blocked by the proxy"}`

### BE-12: The WAF audit log records the attacks and none of the secrets
- **Target:** stack_tls (container log of `proxy`)
- **Preconditions:** BE-06–BE-10
- **Method:** `docker compose logs proxy`; search for rule ids and for the BE-06 password and the BE-07 session token
- **Expected:** a `ruleId` 942xxx and a `ruleId` 941xxx appear; neither the password nor the token appears

### BE-13: A client-supplied X-Forwarded-For does not reach the API log
- **Target:** stack_tls (container log of `api`)
- **Method:** GET /api/auth/me with `Cookie: session=qa-forged` and `X-Forwarded-For: 203.0.113.77`; read `client_ip` of the last `session_rejected` event in the API log
- **Expected:** `401`; `client_ip` is neither `203.0.113.77` nor the proxy's backend address

### BE-14: Container isolation
- **Target:** compose project
- **Method:** `docker compose exec … id -u`; `docker inspect` of the API container; `docker compose port api 8000`; a TCP connect to 1.1.1.1:443 from inside the API container
- **Expected:** API UID 10001, proxy UID 101; API root filesystem read-only, `CapDrop` `["ALL"]`, `no-new-privileges:true`; no published port (empty or `:0`); the connect fails (network `backend` is `internal`)

### BE-15: Login is rate-limited per client IP (run last; it exhausts the limit)
- **Target:** stack_tls
- **Method:** 12 consecutive POST /api/auth/login with distinct unknown usernames and a wrong password
- **Expected:** every answer `401` or `429`, at least one `429` with `{"detail":"Too many requests, try again later"}`, no `5xx`

### BE-16: The Ansible bootstrap certificate is a server certificate with a SAN
- **Target:** none (the `argv` of the task "Utwórz tymczasowy certyfikat TLS do pierwszego startu proxy" in deploy/ansible/roles/patchpoint/tasks/main.yml, run with `patchpoint_domain=helpdesk.example.com` into a temporary directory)
- **Writes:** temporary files only
- **Expected:** `subjectAltName` `DNS:helpdesk.example.com`, `basicConstraints` `critical, CA:FALSE`, `extendedKeyUsage` `TLS Web Server Authentication`
